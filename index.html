02 / Las piezas clave

Seis palabras que
ya conoces.

No hace falta memorizarlo todo. Quédate con qué hace cada pieza y cuándo la usarías.

Repositorio

▤

La carpeta del proyecto más el historial de todos sus cambios. Puede vivir en tu ordenador o en la nube.

git init

Commit

◉

Una foto de un conjunto de cambios. Ponle una nota breve: “Añade el menú”, por ejemplo.

git commit -m "mensaje"

Push

↑

Envía tus commits desde tu ordenador al repositorio remoto para compartirlos.

git push

Pull

↓

Trae los cambios del repositorio remoto a tu copia. Útil antes de empezar a trabajar.

git pull

Rama · branch

⑂

Una línea de trabajo paralela. Prueba una idea ahí sin tocar la versión principal.

git switch -c nueva-idea

Merge

⤴

Une los cambios de una rama con otra. Por ejemplo, al terminar tu nueva función.

git merge nueva-idea
03 / Git y GitHub

Git guarda.
GitHub conecta.

Se parecen en el nombre, pero cumplen papeles distintos. Juntos hacen más fácil colaborar y compartir proyectos.

Git

◉

Es la herramienta que registra versiones de tu proyecto. Funciona en tu ordenador, incluso sin internet.

git commit

GitHub

◎

Es una plataforma web donde puedes alojar repositorios Git, compartirlos y colaborar con otras personas.

github.com

Repositorio remoto

☁

Es la copia del proyecto alojada en GitHub. Con push envías tus commits; con pull recibes los nuevos.

git push · git pull

Pull request

⇄

Es una propuesta para revisar y unir los cambios de una rama con otra. El equipo puede comentarla antes de incorporarla.

Revisar → aprobar → unir

GitHub Pages

↗

Publica como web estática el contenido de un repositorio. Sirve para compartir páginas, documentación y proyectos sencillos.

Repositorio → sitio web

Flujo habitual

⑂

Creas una rama, guardas commits, los subes a GitHub y abres un pull request para revisarlos.

branch → commit → push → PR
03 / Ramas sin misterio

Desvíate.
Vuelve cuando quieras.

La rama main suele ser la versión estable. Abres otra rama para una tarea, haces commits ahí y, cuando está lista, unes el trabajo de vuelta.

Como una copia de tu historia donde puedes experimentar con tranquilidad.

No borras main al crear una rama
